# OffshoreSync — Web3 Conversion Plan

> ZKSync Era account abstraction (passkey login + paymaster) and Self.xyz NFC-passport ZK identity proofs, with all verification happening natively on ZKSync Era — no Celo, no bridge.

This document is the consolidated, authoritative spec for the Web3 conversion. It supersedes the two staging plans under `~/.windsurf/plans/`. Read it top-to-bottom before opening a PR against any of the layers below.

---

## 0. TL;DR

- **Auth**: Passkey + ZKSync smart account becomes the **primary** login. Google / Apple / local password coexist during a transition window, then sunset.
- **Sybil resistance**: Self.xyz passport ZK proof is **mandatory before sensitive actions** (post, comment, apply, recruiter publish, message a stranger). One passport ↔ one smart account, enforced on-chain via a nullifier registry.
- **Devices**: ≤ **3 passkeys per account**, enforced by a custom on-chain validator. Add / revoke flows ship on day one.
- **Gas**: OffshoreSync **paymaster sponsors every user tx** (account deploy, passkey ops, identity bind, future on-chain features) within per-account rate limits.
- **Proof verification**: Self.xyz's Groth16 verifier is **forked and recompiled with `zksolc`**, deployed on ZKSync Era. Proofs are submitted on-chain there in the same tx that binds the nullifier. No bridge, no Celo dependency.
- **Native integration**: First-party Capacitor plugins (`@offshoresync/capacitor-zksync-sso`, `@offshoresync/capacitor-self`) wrap the iOS Swift / Android Kotlin code we port from ZKSync's and Self's RN SDKs. Web path uses WebAuthn + QR handoff to the mobile app for passport scan.
- **Estimated effort**: ~9-10 weeks across 5 phases. Mainnet launch contingent on the Phase 0 spike (specifically: `ecPairing` correctness under `zksolc`).
- **Phase 0 status (2026-05-14)**: ✅ **first gate GREEN** — Self's `Verifier_vc_and_disclose` (Groth16, 21 public inputs) compiles cleanly with `zksolc v1.5.16` + `zkvm-solc v0.8.28-1.0.2`, deploys to anvil-zksync, and `verifyProof(...)` returns `false` (no revert / no OOG) on a known-bad proof. ZKSync's BN254 pairing precompile is exercised correctly under zksolc-generated bytecode. Path A (full on-chain verification on ZKSync Era) is technically unblocked. Remaining Phase 0 work: re-confirm on real ZKSync Era Sepolia + measure actual gas of a real Self-generated proof.

## 1. Locked product decisions

| Decision | Outcome |
|----------|---------|
| Smart account role | **Auth replacement** — passkey login is primary, JWT issuance is gated by passkey signature. |
| Passport proof | **Mandatory before sensitive actions** (not at signup). Verified badge on profile once proven. |
| Self.xyz integration | **Custom Capacitor plugin** (port RN code). No 3rd-party RN bridge shim. |
| Legacy auth | **Coexist for a transition window** (Google / Apple / local password kept for ~2 releases). |
| Passkey cap | **3 per account, enforced on-chain** by `OffshoreSyncAccountValidator`. |
| Paymaster scope | **Full sponsorship** of all user txs; OffshoreSync treasury funds the paymaster. |
| Verifier location | **On-chain on ZKSync Era** (forked Self.xyz verifier compiled with `zksolc`). No Celo, no bridge. |

## 3. Smart contract layer

New repo or `react-server/contracts/`. Tooling: `hardhat`, `@matterlabs/hardhat-zksync`, `@matterlabs/hardhat-zksync-solc`, `zksync-cli`. Gas-budget tracker in CI.

### 3.1 Contracts

#### `OffshoreSyncAccountValidator.sol`
Extends ZKSync SSO's stock passkey validator.
- Enforces `passkeys.length <= 3`.
- `addPasskey(bytes32 credentialId, bytes pubKey, string label)`
- `revokePasskey(bytes32 credentialId)`
- `getPasskeys() view returns (Passkey[] memory)`
- Emits `PasskeyAdded` / `PasskeyRevoked` for off-chain indexing.

#### `OffshoreSyncPaymaster.sol`
`IPaymaster` implementation.
- Sponsors txs only when:
  - `from` is a known OffshoreSync account (deployed via our factory path).
  - The userOp is signed by a currently-registered passkey on that account.
  - Selector is in the sponsorship whitelist.
  - Per-account, per-IP, per-selector rate limits are below cap.
- Whitelisted selectors: account deploy, `addPasskey`, `revokePasskey`, `verifyAndBind`, and a forward-looking allow-list for future on-chain features.
- Sponsorship approval is an off-chain ECDSA signature from a server-side signer key, valid 5 min, verified on-chain (`SignatureVerifier` pattern).

#### `SelfGroth16Verifier.sol` *(forked from Self.xyz)*
- Direct fork of Self's auto-generated Groth16 verifier for the passport circuit we target (`prove_passport` / `register`, to be confirmed in Phase 0).
- **No source edits**; only `zksolc` compile config.
- `function verifyProof(uint[2] a, uint[2][2] b, uint[2] c, uint[N] publicInputs) external view returns (bool)`.
- One deployment per Self circuit version (`proofVersion` constant). New circuit ⇒ new deployment alongside; never mutate.

#### `SelfAttesterRegistry.sol`
- `mapping(address => bool) public trustedAttesters;` (or `bytes32 keyHash` map — resolved in Phase 0 once we know Self's exact TEE key format).
- Owner-only `addAttester` / `removeAttester`. Owner = OffshoreSync deployer key short-term; multisig long-term.
- Initial seed = Self.xyz's published TEE attester set, snapshotted at deploy time.
- Exposes `verifyAttesterSig(bytes message, bytes sig) view returns (bool)`.

#### `NullifierRegistry.sol`
- `mapping(bytes32 nullifier => address account) public nullifierToAccount;`
- Primary entrypoint:

```solidity
function verifyAndBind(
    Groth16Proof calldata proof,
    uint256[] calldata publicInputs,   // [nullifier, scope, country, ...]
    bytes calldata attesterSig,
    address account
) external returns (bool) {
    require(verifier.verifyProof(proof.a, proof.b, proof.c, publicInputs), "bad proof");
    require(attesterRegistry.verifyAttesterSig(_attesterMessage(publicInputs), attesterSig), "bad attester");
    require(publicInputs[1] == OFFSHORESYNC_SCOPE_HASH, "wrong scope");
    bytes32 nullifier = bytes32(publicInputs[0]);
    require(nullifierToAccount[nullifier] == address(0), "passport already used");
    nullifierToAccount[nullifier] = account;
    emit NullifierBound(nullifier, account, uint16(publicInputs[2]));
    return true;
}
```

- Fallback `bind(bytes32 nullifier, address account)` kept behind an `OFFCHAIN_VERIFIER_ROLE`; only enabled if Phase 0 forces us into off-chain verification mode.

### 3.2 What we *don't* fork from Self.xyz
- Self's hub / router / multi-app config contracts.
- Their UI / dapp-glue contracts.
- Their Celo deployment surface (irrelevant to us).

### 3.3 Trust model
- The contract is the **source of truth** for identity verification and passkey state. Mongo mirrors it via an event indexer.
- The indexer is idempotent and re-runnable from genesis to rebuild Mongo state if needed.

## 4. Capacitor plugins

Both shipped as **local packages** under `react-client/plugins/` until stable, then optionally extracted.

### 4.1 `@offshoresync/capacitor-zksync-sso`
Capacitor port of `react-native-zksync-sso` patterns.
- **iOS** (Swift): `ASAuthorizationPlatformPublicKeyCredentialProvider` (Secure Enclave passkeys) + zksync-sso Swift lib.
- **Android** (Kotlin): Credential Manager API + zksync-sso Android lib.
- **JS surface**:
  - `register({ name, userId, rpId, challenge })`
  - `signTx(tx)` / `sendTx(tx)` (paymaster sponsorship attached upstream by `paymasterClient`)
  - `getCredentials()`, `addCredential()`, `revokeCredential(credentialId)`

### 4.2 `@offshoresync/capacitor-self`
Port of Self's RN SDK adapters.
- **NFC adapter**: iOS `CoreNFC` (`NFCTagReaderSession`), Android `android.nfc.tech.IsoDep`. ICAO 9303 passport read (BAC/PACE → DG1/DG2/DG15/SOD).
- **Crypto adapter**: hashing, signing, DSC RSA verification.
- **Documents adapter**: encrypted persistent storage for read passport data (key in Keychain / Keystore).
- **Groth16 prover**: invokes Self's circom witness generator + Groth16 prover (likely a precompiled native lib from Self's mobile SDK).
- **JS surface**:
  - `scanPassport()` → `{ docData }`
  - `generateProof({ scope, salt }) → { proof, publicInputs, attesterSig }`
  - `getNullifier()`

### 4.3 Web fallbacks
- **Passkey**: standard WebAuthn (`navigator.credentials.create` / `.get`).
- **Passport scan**: not feasible in-browser. Web renders a QR code that opens `offshoresync://verify-identity?session=…` on the user's mobile OffshoreSync app, which runs the NFC + ZK flow and submits the proof on-chain. Web polls `/api/identity/qr-handoff/:sessionId` for completion.

## 5. Server (`react-server/`)

### 5.1 Routes

**`routes/auth.js`** (extended)
- `POST /api/auth/passkey-challenge` → `{ challenge, rpId, allowCredentials? }`.
- `POST /api/auth/passkey-verify` → verifies WebAuthn assertion against stored credential pubkey, issues JWT (same cookie shape as existing flows).

**`routes/wallet.js`** *(new)*
- `POST /api/wallet/account` — records `{ smartAccountAddress, network }` after first deploy. Client provides a signed message proving control.
- `GET /api/wallet/passkeys` — list registered credentials (label, addedAt, lastUsedAt only; never pubkey to the client list view).
- `DELETE /api/wallet/passkeys/:id` — server queues an on-chain `revokePasskey` via paymaster session, awaits confirmation, then nulls the Mongo row.

**`routes/identity.js`** *(new)*
- `POST /api/identity/notify` — `{ txHash }`. Server fetches receipt + `NullifierBound` event, updates Mongo immediately. Idempotent with the chain watcher.
- `GET /api/identity/qr-handoff/:sessionId` — web long-poll; resolves once mobile posts a tx hash.
- `POST /api/identity/qr-handoff/:sessionId` — mobile posts `{ txHash }` after on-chain bind.

### 5.2 Middleware

**`middleware/identityGate.js`** *(new)* — `requireVerifiedIdentity`. Returns 403 + machine-readable code `IDENTITY_REQUIRED` so the client can open the inline flow.

Mounted on:
- `routes/posts.js` — create.
- `routes/comments.js` — create.
- `routes/jobs.js` — worker apply, recruiter create vacancy, reveal candidate.
- `routes/conversations.js` — start conversation with a non-friend.

### 5.3 Services

- **`services/paymaster/`** *(new)* — sponsorship signature service, per-account / per-IP / per-selector rate limits, treasury balance monitor with alert at < 1 day burn.
- **`services/chainIndexer/`** *(new)* — `viem`-based watcher for `NullifierBound`, `PasskeyAdded`, `PasskeyRevoked`. Idempotent. Resumes from last processed block stored in Mongo.

### 5.4 Mongo schema changes (`models/User.js`)

Extend `authProvider` enum: `['local', 'google', 'apple', 'zksync-passkey']`.

Add subdocs:

## 7. Migration story for existing users

| Release | State |
|---------|-------|
| N (soft launch) | Both auth systems live, legacy default. Banner + email campaign: "Add a passkey." |
| N+1 | Passkey login default. Legacy still works. `wallet.migrationStatus` tracked per user. |
| N+2 | Legacy auth disabled. Users without a passkey get a one-time email enrolment link. Manual KYC fallback if all devices lost. |

Account recovery (all 3 passkeys lost): user re-proves passport → nullifier matches existing account → server re-binds a fresh passkey to the same on-chain account via a paymaster-sponsored admin path.

## 8. Security & privacy

- **Nullifier hashing**: `keccak256(self_nullifier || OFFSHORESYNC_SCOPE_SALT)` — salt is a server-side env var, never shipped to the client. Prevents cross-app correlation.
- **Passport data never leaves the device.** Only the ZK proof, nullifier hash, and selected public inputs (country, optionally age range) reach our server / chain.
- **Passkey credential public keys** are stored server-side for WebAuthn assertion verification but never enumerated to other users.
- **Paymaster anti-abuse**: rate-limit per account / per IP / per selector / per device fingerprint; sponsorship signatures have 5-min TTL. Specifically `verifyAndBind`: **1 successful call per account lifetime; 3 failed attempts per IP / day**.
- **Stolen device**: revoke from any of the other ≤ 2 devices instantly.
- **All-devices-lost**: re-prove passport → nullifier match → new passkey bound to same account.

## 10. Risks

### Phase 0 blockers
- ~~**`zksolc` codegen for Self's Groth16 verifier.**~~ **Resolved 2026-05-14.** Compiles cleanly, deploys, returns `false` on bad proof. BN254 precompile path verified on anvil-zksync. Real-Sepolia re-confirmation and real-proof gas measurement still pending but no longer rated as blockers.
- **Self.xyz prover on mid-range Android.** Witness gen + Groth16 prover can be 30-60 s on weaker phones. May need WASM-in-worker proving on web.
- **iOS passkey cross-device add** uses Apple's QR + Bluetooth flow; verify it works inside our app (not just Safari).

### Ongoing
- **Self circuit version churn.** New circuit ⇒ new vkey ⇒ new `SelfGroth16Verifier` deploy + paymaster selector update + mobile prover bundle update. Need a 1-day rollout runbook.
- **Self attester key rotation.** If Self rotates TEE keys without notice, our `SelfAttesterRegistry` will reject valid proofs. Build a weekly ops diff tool that alerts on drift.
- **Country public input** may not be exposed by Self's circuit — drop `identity.passportCountry` from the schema if so.
- **Paymaster economics.** Model worst-case daily op count × ZKSync L2 gas → size treasury runway. Alert at < 1 day burn.
